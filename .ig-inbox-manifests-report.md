## Concerns / follow-ups (not done — out of scope for this pass)

1. **`aws-credentials-secret.yaml` bootstrap secret not created.** The
   `aws-secret-store` SecretStore needs an in-namespace `aws-credentials` K8s
   Secret (SOPS-encrypted, per `withings-collector/DEPLOY.md` step 5) to auth
   to AWS SM at all. This machine has no SOPS age private key (`sops -d` on
   withings' own encrypted secret fails: "no identity matched any of the
   recipients"), so it can't be produced here. Left as a commented-out line +
   TODO note in `apps/staging/ig-inbox-uploader/kustomization.yaml`.
2. **AWS SM secrets don't exist yet** — `ig-inbox-uploader/config` and
   `tailscale/ig-inbox-authkey` need to be created (and the ExternalSecrets
   IAM policy extended to allow those paths) before this can reconcile.
3. **Tailscale sidecar state is ephemeral** — used an `emptyDir` for
   `/tmp/tsstate` instead of withings' PVC (not requested/needed for this app).
   Tailscale will re-register on every pod restart; fine as long as the SM
   authkey stays reusable/non-ephemeral (same convention as withings).
4. No `service.yaml` — not requested; the tailscale sidecar proxies to
   `127.0.0.1:8080` inside the same pod, so no ClusterIP Service is needed for
   the app to function.
